\subsection*{1. \texttt{la sp, bootstacktop}}

\texttt{la} 是一条加载地址的伪指令。\texttt{la sp, bootstacktop} 会将符号
\texttt{bootstacktop} 的地址加载到栈指针寄存器 \texttt{sp} 中。
\texttt{bootstacktop} 表示启动栈的栈顶地址。设置 \texttt{sp} 的目的是为后续的
函数调用、返回地址保存以及局部变量分配建立栈空间。

在本实验的 \texttt{entry.S} 中，启动栈通过下面的定义预留：

\begin{verbatim}
bootstack:
    .space KSTACKSIZE
bootstacktop:
\end{verbatim}

当前 \texttt{KSTACKSIZE} $= 2 \times 4096 = 8192$ 字节，因此
\texttt{bootstacktop = bootstack + KSTACKSIZE}。启动栈位于内核的
\texttt{.data} 段中，其最终地址由 \texttt{tools/kernel.ld} 链接脚本决定，
而不是简单固定为 \texttt{0x80000000}。链接脚本将内核的基地址设置为
\texttt{0x80200000}，并对数据段进行页对齐。

需要区分 QEMU 启动过程中的几个地址：CPU 复位后从
\texttt{0x1000} 开始执行，随后进入位于约 \texttt{0x80000000} 的 OpenSBI；
OpenSBI 完成初始化后，将内核加载到 \texttt{0x80200000}，再把控制权交给
内核入口 \texttt{kern\_entry}。

\subsection*{2. \texttt{tail kern\_init}}

\texttt{tail kern\_init} 将控制权转移到 C 语言函数 \texttt{kern\_init}，
开始执行内核初始化代码。该指令采用尾调用形式，不再为返回到
\texttt{entry.S} 额外保存新的返回地址。由于内核初始化完成后会进入死循环，
程序不需要返回到 \texttt{entry.S}，因此使用尾调用可以简化内核启动过程。
