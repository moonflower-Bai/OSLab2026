# Lab4 虚拟内存页操作测试

从仓库根目录运行：

```sh
bash lab4/test/run_vmem_tests.sh
```

脚本依次尝试宿主机单元测试、QEMU 集成测试和模型仿真测试。每层独立构建，前一层失败不跳过后一层。只有三层均实际运行并通过才返回 `0`。临时文件使用 `lab4/test/.vmem-*/`，退出时只清理当次创建的目录；不调用主 Makefile 或评分入口。

## 依赖

- Bash、Python 3.9+ 与 64 位宿主机 C 工具链（默认 `cc`，可用 `CC` 指定）。
- RV64 GCC 工具链（优先 `riscv64-unknown-elf-gcc`，其次 `riscv64-linux-gnu-gcc`，可用 `RISCV_CC` 指定）。
- `qemu-system-riscv64` 的 `virt` 机器、TCG 与默认 OpenSBI 固件（可用 `QEMU` 指定可执行文件）。`VMEM_QEMU_TIMEOUT` 可设定启动至退出的上限，默认 20 秒。

## 如何解读结果

| 层 | 检查内容 | 通过与失败依据 |
| --- | --- | --- |
| 单元测试 | 映射、共享别名、同页更新权限、换页、删除空地址及两级分配失败 | 核对原始叶项、物理页、权限、引用数和释放记录；失败注入后重试并清点中间表页 |
| QEMU 集成测试 | 缓存旧翻译后换页，及可写 → 只读 → 未映射的实际访存 | 无额外刷新直接读取；检查旧别名、写入未污染数据和异常的 `scause`、`stval`、探针 PC；必须观察到 `VMEM_BOOT` 和 `VMEM_DONE PASS` |
| 模型仿真测试 | 两张页表、4 个固定种子各 256 步，跨 2 MiB 和 1 GiB 边界 | 每步对比模型、原始叶项、引用数和缓存翻译；错误时显示种子、步号及截至失败的 `TRACE` 序列，重跑同一入口可复现同种子序列 |

宿主机从实际 `pmm.c` 构建，只在临时副本中将页级/全量 `sfence.vma` 分别接到测试回调，并适配不能在宿主机运行的 CSR、SBI 和原子指令边界。QEMU 直接编译实际 `pmm.c`，用测试启动入口及合法的 Sv39 中间表进行叶项访存。两者都使用可注入故障且可观测回收的测试页池。

如果 `page_insert()`、`page_remove()` 仍只有声明，三层会各自给出链接错误并标为「未运行」，脚本返回 `1`。默认入口没有替代实现，不会把临时对照或错误变体的结果算作仓库实现通过。
