# Design

## Context

见 proposal.md。已逐张查看 12 张 PNG，核对 3 份日志，并比较实验副本与仓库对应的 21 个源码及构建文件；材料与现有入口代码一致。练习 2 的旧日志从内核循环处开始，正确日志则从复位 PC 0x1000 开始。

## Goals / Non-Goals

**Goals:** 用一份说明把每张图片、日志、源码位置和实验结论对应起来；让读者能在仓库内打开完整证据，并区分成功实验与排查记录。

**Non-Goals:** 不修改截图或内核，不将既有镜像无需重建写成从零编译成功，不把入口观察点未触发推广为整个镜像没有写入，不补写成员身份或完整小组报告。

## Decisions

1. 材料放在 lab1/report/record_Lab1/，原图放 images/，成功日志放 logs/，旧会话放 logs/diagnostics/。相较于只提交说明或把整个前置目录导入，此布局保留可点击的证据，同时排除本机工具包和生成镜像。
2. 图片及日志逐字节复制，SHA-256 清单记录来源相对路径、目标相对路径、大小和哈希。相较于裁图、重新生成日志或仅依据截图命名，直接查看内容和哈希核对能保留材料真实性。GDB 原始断点表有两行末尾空格，材料目录的局部 .gitattributes 仅对日志关闭行尾空格检查，保留其他文件的默认检查。
3. 文档说明当前构建的固定地址及 FW_JUMP 适配，提供标准工具的双终端命令。相较于依赖截图中的个人绝对路径，显式固件参数便于其他成员替换实际安装位置。
4. 本变更是已有行为的文档整理，使用 skip_specs: true；保留设计与任务以记录证据分类及验证边界。
5. 根 README 在开发进度的已放入仓库列表中增加材料入口，不在根目录放单章运行命令。使用 Dev/Lab1/hews/exercise-evidence 分支，并只暂存本次文件。

## Risks / Trade-offs

- 原图含本机用户名、主机名和工作路径 → 这些信息是用户明确提供并授权整理的截图上下文；逐图检查未发现密码、密钥或 token，不额外把个人绝对路径复制到说明或 Prompt。原图保持不变。
- 旧日志可能被误当成复位证据 → 放入 diagnostics/ 并在说明中明确其初始 PC 为 0x8020003a，仅作排查记录。
- 固件地址及反汇编受版本影响 → 标明本次配置，复现时先核对固件交接指令，不把地址视为 RISC-V 通用常量。
- 图片中完整 mstatus 解码末尾存在显示截断 → 核心寄存器和 MPP 表达式仍清晰，完整输出由原始日志补充。
- 仓库外前置目录不随提交发布 → 文档提供标准工具参数，并明确 FW_JUMP 路径必须使用实际安装位置。

## Migration Plan

只新增说明和证据并增加入口链接；源材料保留原样。撤销本次提交即可移除导入材料，不影响内核、其他 change 或源目录。
