# Design

## Context

`pmm.h` 声明了待测接口，当前 `pmm.c` 包含分配包装、`get_pte()`、`get_page()` 与 `tlb_invalidate()`，但未定义两个待测函数。测试要能区分实际代码尚未链接与已运行的行为失败。

## Goals / Non-Goals

用相同 PMM 接口在宿主机与 RV64 建立隔离的物理页池和页表。保留实际待测函数以及 `get_pte()` 的代码路径，不运行内核启动自检，也不验证内核引导、通用 PMM 策略或硬件性能。

## Decisions

- 测试设置 `pmm_manager` 为可计数、可注入失败的页池。用叶项、数据页引用及释放事件分别判断映射语义；失败注入使用空目标根及独立的已有映射，单独检查和回收留存的中间页表。
- 宿主机临时副本只适配 RISC-V 的 CSR、SBI、原子指令和 `sfence.vma` 硬件边界；页操作代码不替换、不提供弱定义。地址失效和全量失效分别通知模型。QEMU 直接编译仓库的 `pmm.c`，不做硬件边界替换。
- QEMU 用测试 ELF、启动和 Trap 入口，在 `virt` 上运行实际 S 模式访存。预建 V-only 中间表，避免把 `get_pte()` 当前设置的非叶 `U` 位带入硬件试验；叶项采用合法的访问位组合。Trap 仅从匹配预期的探针指令恢复。
- 模型映射和引用数用扁平状态表推导；实际观察用关掉分配的独立页表读取器。TLB 缓存按根和虚拟页记录，只由相应失效事件清掉，不因修改 PTE 或检查而隐式消失。固定前缀保证覆盖关键操作，后续由固定种子生成；每步先记录可重放操作。
- 三层独立构建，逐项报告及汇总。Python 管理超时和测试目录内的临时目录；宿主机和跨编译报错均保留原诊断。若接口未定义，另用测试临时副本上的正向对照与三个独立变体验证断言，不在默认构建中加入临时实现。

## Risks / Trade-offs

- QEMU 可能偶然丢弃旧翻译，不能单独保证检出遗漏失效；确定性 TLB 模型补足这个覆盖缺口。
- 宿主机适配面依赖实验提供的 CSR 入口及 `sfence.vma` 指令写法；不支持的硬件汇编应暴露为构建失败，不能伪装成一个已经执行的失效操作。
- Prompt 证据仅存放人工复核、不含敏感值的相关原文，不复制其他会话或 change 的内容。

## Migration Plan

添加独立测试入口，不接入现有编译或评分流程。接口实现后直接重跑脚本；回退时只移除本次测试与 OpenSpec 记录。
