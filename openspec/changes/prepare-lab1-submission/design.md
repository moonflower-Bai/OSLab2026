# Design

## Context

动机和实际缺项见 proposal.md 与 audit.md。当前章节是 lab1，源码为课程提供的最小启动骨架。前置目录与 Git 仓库并列，其本地工具、绝对路径和包装脚本不会随克隆获得。已在副本重新确认构建与内核横幅；GDB 观察仍来自前置日志。

指导书练习及报告要求页没有取得正文。本设计只实现已确定的复现和材料组织行为，不决定未知题目对应的内核修改。队友报告仍是未整合的 LaTeX 草稿。

## Goals / Non-Goals

**Goals:**

- 给个人贡献提供独立、可执行的验证工具和小体积证据，而非仅重复上传骨架。
- 从标准工具命令复现启动和调试，不依赖前置目录的隐藏适配。
- 将材料完整性检查与 Git 提交操作分开，缺项可以明确暴露。
- 将课程 Prompt 交付例外限制在两个具体位置，维持现有隐私边界。

**Non-Goals:**

- 不改动内核功能，不承诺未知练习二的所有操作或 Challenge 已完成。
- 不在这一步创建最终 lab1 分支；该分支是否保留额外治理文件在实际创建前单独确定，不能在这里把当前工作树直接搬成 code/report。
- 不把工具包、GDB/QEMU 二进制、node_modules 或生成的内核文件加入提交，不覆盖队友草稿。

## Decisions

### 1. 验证实现留在当前章节

新增 lab1/scripts/check_env.sh、verify_boot.py、verify_debug.py；源码和链接脚本保持原样。脚本通过可覆盖的参数或标准命令查找工具，调试器优先使用 RISC-V 命令名并兼容 gdb-multiarch。环境检查输出实际版本、目标架构和缺项，默认不安装软件。

把个人工作放在 Dev/Lab1/hews/prepare-submission。先前建议的环境与调试分工作为本提案的建议范围，不据此宣称小组已正式分配练习。

替代方案是复制现有 .tools 和绝对路径包装脚本；这会扩大仓库且不能在其他机器直接复现，因此不采用。

### 2. 自动运行显式处理固件交接

验证入口默认使用 QEMU virt 的 -kernel 方式加载同一原始镜像，配合标准固件启动，避免旧 Makefile 的 loader 方式在当前 FW_DYNAMIC 下没有 next_addr 的问题。前置对照日志已显示该方式可输出横幅；Apply 中必须重新运行并保留结果。可显式提供固件和 QEMU 路径，但不偷偷修改系统固件或课程 Makefile。

启动工具先执行有限时长的 make，再启动 QEMU；观察指定横幅后结束进程。成功条件是构建成功且横幅出现，程序被主动终止的状态与内核错误分开记录。

替代方案是直接修改 Makefile 固件路径；固定个人安装路径不便于协作。本 change 先提供标准验证入口，是否调整课程运行目标在取得完整题目后另行决定。

### 3. GDB 证据来自本次 ELF 和实际运行

调试工具选择本机回环端口，启动暂停的 QEMU，再批量执行 GDB。检查复位 PC、kern_entry、设置启动栈后的 sp 与 bootstacktop 符号、kern_init。入口和栈符号从本次 ELF 解析，不写死 0x80203000。

QEMU 与 GDB 都有时限，退出时清理自己创建的进程组。输出明确说明继续运行命中入口与单步观察的区别，不把这些检查扩充为未读练习的完整答案。

替代方案是人工双终端验证；文档保留人工步骤，自动入口用于可复现提交和失败诊断。

### 4. 文档、个人材料和最终报告分开推进

lab1/README.md 提供工具要求、构建、运行、调试与退出步骤。lab1/docs/requirements.md 记录任务依据和缺项；lab1/docs/defense.md 按源码整理知识点。lab1/report/hews-validation.md 记录个人实际工作，不能冒充完整小组报告。

本次工具产生的文本证据记录命令、时间、代码版本及工作区状态，和前置日志区分。小体积文本可以进入 Git；真实终端截图由实际操作的人提供。完整 report.md、成员与模型信息、课程 Prompt 和图片由小组明确提供后整合。

### 5. 导出工具只整理完整输入

scripts/export_lab1_submission.py 接收当前章节和报告目录，将代码与完整报告导出到仓库外新目录。输出固定为 code/ 与 report/；代码排除构建产物、下载目录和本地工具。导出文本统一 LF，但不修改源文件；除此之外保留源码内容。

工具检查 report.md、prompt.md、images/ 和报告引用的本地图片，拒绝缺项、未完成占位和已有内容的目标。先检查全部输入，再写入新目录；失败不留下可误认为完整交付的成品。人工题目覆盖审查仍独立于文件结构检查。

替代方案是手动复制和搬动工作树；独立导出能够维持 lab-status.json 与当前章节布局，并允许先检查交付结果。最终 Git 分支与提交操作在用户授权后另行执行。

### 6. 课程 Prompt 使用精确路径例外

保留 OpenSpec change 证据现有路径与格式。新增课程材料类别，只允许当前章节的 lab1/report/prompt.md 与根 report/prompt.md；课程格式包含实验标识、记录时间及人工相关性/敏感性声明，不要求伪造 change 名称。

修改 AGENTS.md、prompts/README.md、openspec/config.yaml 和治理检查，明确课程汇总是用户主动提供的单独材料。普通学习问答不会因此自动落盘，其他 change 或旧会话不会被读取、复制或迁移。敏感值仍整条拒绝，不生成脱敏副本；自动扫描只报告文件位置且不改写内容。

替代方案是放开所有名为 prompt.md 的文件；这会扩大保存范围，故只增加精确、可测试的例外。现有未归档 restrict-prompt-archive 与本 delta 需在未来归档时共同审查，本次不归档它。

## Risks / Trade-offs

- 正式题目全文不可读 → 清单保留未核对状态，工具验证结果不能写成全部练习或评分通过；取得正文后才整合最终逐题报告。
- 不同机器的工具和固件版本不同 → 提供显式工具选择，记录真实版本并实际验证；缺少条件返回失败。
- 已有源码包含 CRLF，课程导出可能触发行尾门禁 → 只规范新文件和导出副本，避免重格式化整个内核。
- 课程 Prompt 与现有规则冲突 → 实施有限例外并增加合法路径、非法路径、敏感值和缺少声明的验证样例。
- 个人身份和模型使用记录尚未提供 → 不填写猜测值，不从其他 Prompt 推断；在组内报告整合时由成员提供。
- 文本输出不等于真实终端截图 → 文本用于复现与追溯，截图缺项仍单列。

## Migration Plan

1. 在当前个人开发分支按 Apply 任务实现章节内工具与文档。
2. 实际验证工具成功与失败路径，保存证据并审阅个人 diff。
3. 实施课程 Prompt 的有限例外及独立交付导出工具；用临时样例验证结构、缺项和覆盖拒绝行为。
4. 用户提供完整课程材料后审查题目覆盖并导出；额外文件及最终分支布局在创建分支前确认。
5. 用户分别授权 Git commit、push/PR、归档和最终交付分支操作；本提案和 Apply 本身不触发这些操作。

回退时仅撤销本 change 新增工具、文档与门禁例外；既有内核、工具安装、队友分支和仓库外历史证据不受影响。
