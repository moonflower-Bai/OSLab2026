## Context

动机与范围见 `proposal.md`。初始实施分支为 `Dev/Lab2/hews/setup`，基线为 `origin/Dev/Lab2/main` 的 `d52989b`；以下是初始设计背景，个人提交范围按顶部的分工调整执行。

骨架的 `pmm.c` 缺少 `page_init()`，且仍选择 First Fit；`best_fit_pmm.c` 缺少管理器实现，只保留框架检查。提供的评分脚本检查初始化和 Best Fit 各 10 分，但分配算法的实际行为主要由启动时的 `best_fit_check()` 保证。最终验收需要同时检查自检和评分，不能仅凭管理器指针或输出字符串判定正确。

课程要求提交分支根级包含 `code/`、`report/`；仓库开发规范要求章节隔离。远端 `Lab1` 已采用根级交付目录，但这不等于当前治理脚本能无修改接受同样的 Lab2 整理过程。

## Goals / Non-Goals

**Goals:**

- 将内存初始化与分配算法按依赖顺序实现，使故障能定位到启动环境、页布局或分配器。
- 保留原始骨架和框架测试作为核对依据，采用独立于测试输出的内存状态不变量检查实现。
- 明确代码完成、测试完成、报告完成和最终交付完成四个不同状态。

**Non-Goals:**

- 不将本 change 扩展到 Lab3、中断、进程或运行时页表管理。
- 不安装全局工具或复制另一套工具链进仓库。
- 不把交付规则冲突暗中转化为治理规则变更；最终发布整理在本 change 之后另行审阅。

## Decisions

### 1. Use a chapter-isolated development tree

复用用户指定集成分支的布局，不重新搬动其骨架：

```text
lab2/
├── AGENTS.md
├── Makefile
├── kern/
├── libs/
├── tools/
└── report/
    ├── report.md
    ├── logs/
    └── images/
```

基线的 39 个骨架文件已逐字节对照原始目录，无差异。基线已移除 Lab1 目录，后续只比较相对 `origin/Dev/Lab2/main` 的改动，不将其重新导入。将当前章节切换为 `lab2` 并同步根 README 的实际进度，保留 `frozen` 原值。

提交按四组组织：开发配置与本 change；物理内存初始化及其验证、说明；Best Fit 及其验证、说明；综合验证与报告交接。首次配置提交保留原始骨架已知编译失败，后续功能提交须有对应可复现的成功检查。每次只暂存本阶段相关路径，不推送或重写已共享历史。

### 2. Reuse tools but verify the Lab2 boot interface

本机已有 `../Lab1前置准备/bin/`，已验证 QEMU 10.2.1、GDB 17.1 和 OpenSpec 1.14.0 可以启动。RISC-V GCC、Make、Python 和 `bc` 已在 PATH 中。

现有 QEMU 包装脚本会为旧式 loader 启动选择 OpenSBI FW_JUMP。Lab2 还依赖固件传入 DTB 地址，因此实施时需要核对 DTB magic、内存范围和跳到内核后的地址映射。仅当发生启动问题时用 GDB 检查 `a1`、`boot_dtb` 和页表交接；在确认环境原因前不改写启动汇编或评分测试。

骨架缺失实现导致的编译失败记录为代码基线，不当成工具缺失。正常空转导致的限时退出也与 panic、启动挂起分开记录。

### 3. Establish the memory map before changing the allocation policy

先用已有 First Fit 管理器验证 `page_init()`。未完成的 `best_fit_pmm.c` 本身也参与编译，现有检查引用了尚未声明的 `free_list` 和 `nr_free`；因此该阶段先补齐 Best Fit 的共享空闲区声明及对应宏，使该编译单元可构建，但仍不启用其分配策略。其中：

- `va_pa_offset` 对应已有内核映射常量。
- `npage` 对应 DTB 内存末端的物理页号，描述符数组项数使用 `npage - nbase`，不能把二者混用。
- `pages[]` 放在链接符号 `end` 之后并按页对齐；先保留已知物理页，再将描述符数组末端之后的完整可用页交给 `init_memmap()`。
- 使用实际结构体大小计算描述符空间，检查边界和对齐，不将默认 128 MiB 写死为探测结果。

初始化自检通过后再接入 Best Fit，避免同时改变页布局和分配策略。已有高地址映射与页表仅作为需要理解和验证的框架，本次不另造页表系统。

### 4. Keep the free list ordered by physical address

Best Fit 复用框架的双向链表和块首描述方式，空闲块按物理地址排序。申请时遍历寻找最小足够块，等大候选自然采用先遇到者；分配后保留剩余空闲块。释放时按地址插入并检查前后相邻块，实现双向合并。

按大小排序也便于选取块，但会增加邻接查找和合并维护；本实验选择地址有序，分配复杂度为 O(空闲块数)，与现有框架规模相适应。

关键不变量是：空闲块不重叠、地址有序、相邻空闲块已合并、仅块首标记空闲块长度、`nr_free` 等于所有空闲块页数之和，已分配页不在空闲链表。保留原有 `basic_check()`、`default_check()`、`best_fit_check()` 及评分工具原文。

### 5. Validate layers and preserve authentic evidence

依次验证：编译与 ELF → 默认内存下启动 → 分配器框架自检 → `make test` 的检查进度 → `make grade` 的 20/20 → 非默认内存规模下的初始化。

需要切换测试编译宏时先清理，避免复用旧目标文件。自动启动命令加外部限时并记录成功标记、退出原因和本次进程清理情况。优先使用原有检查；对确实未覆盖的必要边界，可在临时副本增加独立验证，不能通过修改原测试降低标准。

报告保留实际日志的对应关系和真实终端截图。组员、负责人、迭代次数等只能来自实际输入与记录，未知值明确标注，不以示例内容填充完成状态。

### 6. Treat final submission preparation as a separate handoff

本 change 准备 `lab2/report/report.md`、截图及可审阅的目录映射说明。提示词原始证据仅保存于本 change 的 `prompt.md`，人工核对相关性与敏感性，不读取其他 change 的提示词来补全材料。

最终课程交付需要根级 `code/`、`report/` 和 `report/prompt.md`。当前提示词门禁禁止后一个路径，章节目录整理也需检查范围门禁。因此最终整理是已识别的后续工作，需单独形成具体调整方案；本次不生成被禁止的受版本管理提示词副本，不声称发布已准备完毕。

个人提交路线为 `Dev/Lab2/hews/page-init → Dev/Lab2/main → Lab2`。用户已授权个人 commit 与推送，两阶段合并均使用 Rebase and merge；远端合并、发布分支创建与归档尚未授权。完整参考分支保留在本地。

## Risks / Trade-offs

- 指导书练习正文尚未取得 → 当前契约只承诺骨架和本地资料已确认的功能；核对正文后，将额外要求分类并另行确认实质增量，完整课程验收不提前标记通过。
- QEMU/OpenSBI 能运行 Lab1 但未必正确交接 Lab2 的 DTB → 优先验证启动参数和 DTB，必要时用 GDB 定位，避免把固件问题误归因于分配器。
- 最小评分脚本主要核对标记和管理器选择 → 同时要求框架自检成功、链表不变量成立及日志无 panic。
- 非默认内存规模暴露硬编码 → 增加一次 64 MiB 启动检查，核对 DTB 报告和 `npage` 的一致性。
- 课程提示词交付要求与仓库门禁冲突 → 在最终交付前单独审阅必要调整，不自动放宽治理规则。
- 报告和提示词可能包含个人信息或凭证 → 只保存符合当前规则的必要证据；敏感用户消息仅作无内容的省略记录，不复制到报告或截图。

## Migration Plan

1. 复用用户指定的 Lab2 基线，核对已确认范围，补齐章节配置。
2. 先验证内存初始化，再实现并启用 Best Fit，最后完成验证和报告。
3. 以已核对的骨架清单和集成分支作为对照；出现问题时在当前开发分支局部修复，禁止通过重置他人工作或修改原始目录回退。
4. 本 change 完成后，将未解决的课程正文、提交布局和提示词导出约束明确交接；另行完成发布整理和授权后的分支流转。
