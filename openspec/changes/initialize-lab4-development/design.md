# Design

## Context

动机见 proposal.md。工作区初始干净，当前分支为 `Dev/Lab4/main`，本地已有 `baijingren` 的实验开发分支，可沿用该标识。`lab-status.json.current` 为 `lab3`，`frozen` 为空；当前检出仅含 Lab4 源码，实际 Makefile 位于 `lab4/lab4_new/`。已有 OpenSpec 1.13.1、GCC 16.2.0、QEMU 11.1.2，AI 工作流检查通过。

## Goals / Non-Goals

**Goals:** 使用已有 Makefile 作为实际构建入口；通过本地状态修正、文档和基线验证形成可继续开发的起点。

**Non-Goals:** 不将编辑器用 CMake 工程当成内核构建入口；不迁移目录，不补写进程管理练习，不增加测试或改变评分标准。

## Decisions

- 状态采用 `lab4`，不自动冻结或恢复历史章节。依据当前分支与现有源码，避免用过时 README 的 Lab1 信息反向覆盖真实状态。
- 用户后续明确要求保留当前 `Dev/Lab4/main` 分支，因此本次不创建或切换分支，不提交。未来分支切换与提交在后续任务处理；本次治理验证按当前 stable 角色检查，目标为 `Lab4`。
- 先使用已有 `riscv64-unknown-elf-` 工具链与 QEMU；有必要时通过 Makefile 现有变量覆盖。仅对证明属于环境兼容的构建故障做最小修正。
- 本机实测默认固件配合 `-device loader` 时 OpenSBI 的下一入口为零，无法启动已加载的最小程序；同一二进制配合 `-kernel` 时入口为 `0x80200000`，UART 输出成功。因此将 Makefile 的运行、调试入口与现有评分脚本的加载参数统一为 `-kernel`，不改任何练习代码、评分断言和分数。
- QEMU 验证设置时间上限，保存输出并终止本次创建的进程；评分使用独立临时目录覆盖 `GRADE_TMP`，避免复用固定 `/tmp/lab4_grade`。
- 根 README 只改进度，命令留在 `lab4/README.md`。验证结果记录在当前 change 的 `verification.md`，不把初始化等同于练习验收通过。
- Prompt 仅收录人工确认相关且无敏感内容的两条用户原文，不读取其他 Prompt 证据，不保存机器账号或凭据。

## Risks / Trade-offs

- [较新 GCC 默认指令集可能与汇编不匹配] → 先实测，优先使用现有编译变量覆盖，不预先修改代码。
- [骨架缺少练习实现导致构建或启动失败] → 单独验证工具链与 QEMU，保留实验功能，记录具体阻塞。
- [现有评分脚本在 macOS 上依赖 GNU 工具或调试器] → 检查命令与输出，报告环境差异，不改评分规则。
- [治理脚本可能存在历史文件依赖] → 如实记录既有失败，只修正本次范围内问题。

## Migration Plan

严格校验本 change 后保留当前分支，更新章节状态与文档，再进行构建、限时启动及现有评分验证。修改保留为工作区 diff，不提交或推送；需要回退时可依据实际 diff 单独恢复本次文件。
