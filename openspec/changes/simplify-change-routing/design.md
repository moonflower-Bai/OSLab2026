# Design

## Context

动机见 proposal.md。已检查的根规则、配置和 README 都要求所有修改先规划；Cursor 入口还重复了阶段约束。`scripts/check_governance.py` 检查阶段名称、章节范围和规格有效性，但没有要求每次 diff 都存在新 change，因此直接处理不需要增加新的 schema 或 CLI 功能。

已有 `harden-ai-development-governance` 完成但未归档，其 delta 仍包含全量规划要求；主规格暂时只有 `root-readme` 和 `prompt-archive`。本次新增聚焦分流的 `change-routing`，不改写旧 change 的历史意图。

## Goals / Non-Goals

**Goals:** 在唯一根入口决定是否调用 OpenSpec，所有平台复用该判断；规则能区分恢复契约与改变契约，把实施批准绑定需求范围并持续复用，且能用有限的自动检查发现已知回退。

**Non-Goals:** 不做按行数的自动风险分类器，不更换 schema，不批量重写或归档旧 change，不读取旧 Prompt，不修改各平台的命令语法及 CLI 状态语义。

## Decisions

### 先分流，再选择技能

在 `AGENTS.md` 中先识别明确实施批准或快速、直接修改请求，再判断直接维护与完整流程。明确直接实施的范围立即执行，已有 change 时复用；没有 change 时不把四件套作为先决条件。仅要求提案或探索的请求保留规划边界。

默认直接路径适用于恢复既定行为的局部 bug、纯文档和 LaTeX 编辑，以及不改变契约的局部整理。没有明确直接实施授权时，完整路径适用于新实验能力、规格契约变化、跨模块重构、治理策略调整，或用户明确请求规划审阅。混合请求不能用文档后缀隐藏实质代码变化；先做相关只读检查，仅在具体需求存在关键歧义时澄清。

### 同步 48 份平台提示词及可重放的本地适配

已枚举本仓库五类技能目录和三类命令目录，共 48 份提示词。修改 propose 的无条件规划暂停、apply 的遇错即停、update 的逐产物确认、explore 的已有授权仍需新消息，以及 archive 的已有归档/同步授权仍重复选择等条款；sync 保留规格合并和验证边界。所有提示词用相同短引导引用 `AGENTS.md`，不建立另一份独立的授权规则，保留各平台命令拼写、YAML frontmatter、CLI 根选择和文件完整性检查。

新增 `scripts/sync_ai_workflows.py`，集中维护适配规则，`--write` 幂等恢复本地条款，`--check` 检查缺失或回退。治理门禁调用只读检查；README 说明执行 `openspec update` 后重放本地适配。仅加入口引用而保留正文固定暂停会继续造成冲突，故同时修改正文。为当前 CLI 版本适配；遇到未知模板不能静默声称兼容，检查应指出待审阅文件。

### 同步摘要，不复制第二份判断标准

配置以 context 描述两条路径，apply guidance 仅约束完整流程。README 和 Cursor 引导简要说明分流并指向根规则。`prompts/README.md` 增加无 change 直接处理不留存的说明，根规则的 Prompt 段落同步这一前提。

完整流程区分各操作的授权内容，直接维护的修改请求已经授权该维护，不再要求第二次 apply。Git commit 和 archive 仍需用户明确要求，但这些要求可以与实施指令在同一条消息中给出；满足条件后执行，不再要求用户为同一授权重复表态。冻结章节限制不因文档类型或修改量而放宽。

### 一次实施批准持续覆盖需求范围

使用需求、行为契约、验收标准和允许的实质范围判断授权边界，不把 checkbox、文件数或对话轮次作为新审批点。批准后连续完成实现、局部设计调整、失败后的修复、必要的验证及关联文档和已有规划同步；这些维护不需要再次 Propose 或 Apply。

新功能、契约改变、验收标准改变、实质扩大范围属于未批准增量，先说明新增内容和影响，再针对增量确认。与增量无依赖的原工作继续推进；不把代理自行提出的建议当成用户批准。用户明确提出并授权直接实施具体增量或快速修改时复用这条授权，不再要求另一条 apply 消息。仅表态偏好、询问状态或只要求修改提案不等于批准实施。

用户明确停止或撤回时授权失效；用户要求继续、原授权仍适用时不再索取 apply。本次用户在审阅现有提案后要求继续修改授权逻辑并同步各工具提示词，按该明确修改请求实施已有 change；不授权归档或提交。

备选是每修改一个产物、执行一项任务或遇到失败都停下来，会把同一需求拆成大量重复审批，故不采用。更新本地生成技能中的固定暂停条款，让范围内产物同步直接完成；用户仅要求某个规划工作流时只做规划，同时优先识别随请求给出的明确实施批准。

### 检查已知回退，不伪装成语义分类器

扩展现有 `rule_violations` 及其调用，校验根规则的两条路径声明、配置及 README/Cursor 中已知的一刀切旧表述；添加有效规则和旧规则回退的自检样例。保留章节、行尾、Prompt 和 OpenSpec 校验，不要求每个维护 diff 创建 change。自动检查只能防止已知不一致，分流仍需根据任务人工判断。

验收包括：局部恢复两行 bug → 直接；两行改变中断契约 → 完整；纯 LaTeX 内容/排版 → 直接；新增实验 → 完整；已授权范围内修复、失败后重试及产物同步 → 连续完成；代理新增功能建议或放宽验收 → 仅确认增量；明确追加并实施的授权 → 不重复询问；跨轮继续 → 沿用批准；一次授权多操作 → 满足条件后执行；冻结章节维护 → 阻止；明确请求提案 → 提案边界。场景通过规则审阅验证，不为了演示而修改内核或文档。

### 无 change 就不新增 Prompt 记录

直接维护留下实际 diff 和验证结果；没有 change 时不创建证据文件，不引入另一套归档。存在对应 change 时沿用已有相关性和敏感性审阅规则。本次用户请求经人工检查与变更直接相关且无敏感值，原文仅保存在本 change 的 prompt.md。

## Risks / Trade-offs

- [把行为变化误认作小 bug] → 明确恢复已有契约与改变契约的区别，不按行数、扩展名或文件数分类。
- [历史 delta 在未来归档时重新引入全量规划] → 本次声明分流规则优先于历史一刀切条款；后续获准同步旧治理 change 时先协调冲突，不能直接恢复旧授权语义。本次不擅自改旧记录。
- [规则关键字检查不能证明 AI 会正确执行] → 自检仅保证已知规则回退被拒绝，验收另包含逐项场景审阅。
- [把持续授权误解为任意扩大需求] → 明确行为、验收和范围增量需确认，区分用户授权、代理建议及提案修订，撤回时立即遵从。
- [OpenSpec 更新覆盖本地适配] → 集中脚本重放修改并由治理检查检测回退，未知模板需要审阅而非直接替换全部正文。
- [直接维护失去 Prompt 证据] → 接受这一减负取舍；涉及完整规格变更时仍有 change 证据，敏感原文在任一路径均不得留存。

## Migration Plan

获准 Apply 后一起更新根规则、配置和短引导，再补齐规则检查及自检；范围内任务、修复和产物同步连续完成。运行治理检查与规格校验，审阅两条路径和授权延续的典型场景；本次不修改实验实现，不需要内核构建或 LaTeX 编译。回滚恢复本次触及的治理文件即可，不影响章节实现。实施结束仅在尚无明确归档或提交授权时等待相应授权。
