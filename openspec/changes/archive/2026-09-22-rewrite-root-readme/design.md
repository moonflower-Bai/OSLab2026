# Design

## Context

现有 `README.md` 的顺序是简介、进度、lab1 构建、CI、OpenSpec、Prompt。见 proposal.md 的 Why。

## Goals / Non-Goals

**Goals:**

- 三个固定章节：指导书、开发进度、开发规范。
- 指导书用列表呈现章节，而不是一段介绍。
- 规范集中在进度之后，用短列表写跨章节约定。

**Non-Goals:**

- 不在根说明里写某一章怎么编译。
- 不改 `prompts/README.md` 或各 harness 的启动说明。

## Decisions

### 三个一级标题，按固定顺序

1. 指导书：入口链接，其下按 lab0、lab0.5、lab1 至 lab9、附录列出。目录里暂未显示的 lab2 至 lab9 仍给出直达链接，并在该项下注明侧边栏状态。
2. 开发进度：已在仓库中的内容和尚未放入的章节。
3. 开发规范：章节隔离、只测当前章、OpenSpec、Prompt 归档。细节用指向 `prompts/README.md` 的一行带过，不把归档规则再讲一遍。

备选是继续用现在的散文并只删掉构建命令。那样顺序和拼凑感还在。

## Risks / Trade-offs

- [指导书页面以后改名，链接会失效] → 只链到各章入口页，不链到章内每一小节。
- [进度和规范以后再变长] → 进度保持状态列表；规范保持短条目，细节留在各自的说明文件。
