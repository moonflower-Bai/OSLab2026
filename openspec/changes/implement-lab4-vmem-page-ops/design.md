# Design

## Context

`get_pte()` 已负责查找和分配中间表，`pte_create()` 自动加入 `PTE_V`，页分配接口和 `struct Page` 已提供引用管理。末级项的写入和数据页的所有权变更由本次补齐的接口负责。

## Goals / Non-Goals

**Goals:** 保持叶项、数据页引用和本地缓存翻译的一致性，不改变实验既有接口和验收。

**Non-Goals:** 不重写 `get_pte()` 或物理页分配器，不清理空中间表，不新增地址空间切换或远端 hart 的 TLB 同步机制。

## Decisions

- 插入先用 `get_pte(pgdir, la, 1)` 完成可能失败的查找。`create` 沿用仓库的整数 `bool` 约定。失败时立即返回，不先碰数据页引用，也不回滚已由 `get_pte()` 挂接的空表。成功后根据旧叶项的 `PTE_V` 取旧页；仅首次映射或换页增加目标页引用。同页更新不通过「先删除、再插入」周转引用，以免误回收唯一引用的数据页。
- 一次写入由目标物理页号和新权限构造的叶项，不合并旧权限。无有效旧叶项时，`get_pte()` 可能刚挂接了非叶项，采用 `flush_tlb()` 所用的全量 `sfence.vma` 形式，避免额外遍历。已有有效叶项时复用按虚拟地址失效的 `tlb_invalidate()`。两种指令在本次页操作中均带 `memory` clobber，约束编译器在指令前提交 PTE 写入。
- 替换直接写新叶项后失效，随后减少旧页引用，降至零才释放。删除用 `get_pte(pgdir, la, 0)` 找到有效叶项，保存旧页、清零并失效后，再减少引用和按需释放。这样分配器不能在失效前重新分配旧页。

## Risks / Trade-offs

- 首次映射即使未新建中间表也全量失效，代价是可能清掉无关的缓存翻译；换页、权限更新和删除只针对目标地址。
- 现有自检依赖框架的非叶 `PTE_U` 约定，不改该约定。现有 QEMU 用例预建合法的非叶项，验证实际叶项翻译；中间表的分配和失败重试由宿主机单元测试与模型覆盖。
- 无需改动现有自检或评分来处理其它模块的构建阻塞。独立脚本的通过结果不等同于完整内核可构建或可启动。

## Migration Plan

无接口迁移。使用现有独立测试入口验证，若回退则只撤回本次页操作和相应 TLB 辅助的改动。
