# Design

## Context

当前规则在每条消息到达时按外部会话号追加原文，见 proposal.md 的 Why。作业真正需要的是能够解释一个实现 change 的用户输入，而不是完整聊天；同时姓名等自然语言敏感信息无法由正则可靠识别。

## Goals / Non-Goals

**Goals:**

- 让每个实现 change 自带可提交、可审阅的原始 Prompt 证据。
- 在任何文件写入之前先做相关性和敏感性判断。
- 敏感消息采取整条拒绝策略，不产生容易误解为原文的脱敏版本。
- 用同一个本地检查入口和 GitHub Actions 阻止明显违规提交。

**Non-Goals:**

- 不保存完整聊天记录，不保存助手回复或工具输出。
- 不承诺自动扫描能识别所有中文姓名或上下文相关隐私。
- 不读取或批量迁移其他会话的旧 Prompt 文件。

## Decisions

### change 是 Prompt 证据的归档单位

合格原文写入 `openspec/changes/<change>/prompt.md`；归档后随 change 移动到 archive。文件包含 change 标识和按时间排列的用户原文。一个 Prompt 同时影响多个 change 时，可以分别收录，但必须由各 change 的实际范围支持。

备选是继续维护按会话文件并在提交时筛选。那仍会先把敏感内容写入磁盘，也无法明确哪段对话对应哪个实现。

### 写入前执行两道判断

第一道判断消息是否直接创建、修改、应用 change，或改变需求、设计、任务、验收条件；否则不保存。第二道判断是否包含姓名、学号、身份证明、账号凭证等敏感信息；命中时整条不保存。

如果敏感消息确实改变了 change，只允许写入一条时间和 `omitted: sensitive-input` 标记。具体需求由 OpenSpec 产物表达，但标记不复述原文。

### 不进行脱敏改写

脱敏副本容易遗漏敏感片段，也不再是可证明的原始 Prompt。因此策略只有“原样保存”与“整条拒绝”两种状态。

### CI 是拒绝门禁，不是隐私证明

治理脚本检查 Git 跟踪内容：禁止新增按会话归档；Prompt 证据只能位于 change 的 `prompt.md`；扫描带字段上下文的学号、姓名、身份证号和常见凭证模式；拒绝 `<redacted>` 等脱敏占位符。检查只返回非零状态和位置，不修改文件。

中文姓名无法可靠自动识别，因此 `prompt.md` 还必须声明已经人工检查敏感性和实现相关性。声明是责任记录，不替代审阅。

### 遗留会话文件不进入后续提交

`.gitignore` 忽略 `prompts/` 下的会话 Markdown，但保留 `prompts/README.md`。实现只处理本会话中已经获准读取的文件；其他会话既不打开也不迁移。

## Risks / Trade-offs

- [自动扫描漏掉姓名或新格式学号] → 保留人工检查声明，CI 明确不作完整安全保证。
- [过严模式误报讨论隐私规则的 Prompt] → 模式要求出现字段和值的组合，而不是只匹配“姓名”“学号”这些词。
- [敏感 Prompt 被省略后无法还原原始措辞] → 这是明确的隐私优先选择；OpenSpec 只保留不含敏感信息的行为要求。
- [change 创建前无法确定保存路径] → 先在当前轮内存中判断，CLI scaffold 成功后再把合格原文写入 `prompt.md`。

## Migration Plan

1. 更新 Prompt 规格和仓库级入口，停止新的会话追加。
2. 给两个当前 change 创建各自的 `prompt.md`，只收录本会话中直接相关且无敏感值的原文。
3. 更新 `.gitignore` 和 `prompts/README.md`，把其他会话文件留作本地遗留内容。
4. 扩展治理脚本和 GitHub Actions，验证允许路径、明显敏感模式和人工检查声明。
5. 验证后等待用户授权归档；回滚时恢复旧入口，但不自动恢复或读取遗留会话内容。
